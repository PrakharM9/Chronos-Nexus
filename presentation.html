🕒 Chronos-Nexus

An AI-powered Temporal Contradiction Engine that analyzes how facts evolve across time — revealing reversals, shifts, and contradictions from 2024 → 2025 → 2026.

LangGraph RAG Pipeline Groq / Grok / Gemini Tavily Search Streamlit ChromaDB
The Problem

Why Static AI Fails

🤖

Static Answers

Normal chatbots give one answer based on training data, ignoring how facts have evolved over the years.

⏳

Outdated Information

In finance, politics, and healthcare — truth changes. A fact true in 2024 may be completely reversed by 2026.

❌

No Contradiction Detection

Standard RAG systems assume truth is static. They cannot detect when their sources contradict each other across time.

💡 Chronos-Nexus solves this by showing what was true, what changed, and what is true now — for any topic.

Features

What Chronos-Nexus Does

🔍

Temporal Web Search

Searches the live web 3 times — once for 2024, 2025, 2026 — using Tavily's AI-optimized search engine.

🧬

RAG Pipeline

Embeds yearly results using Gemini Embeddings into ChromaDB, then retrieves the most semantically relevant chunks.

⚡

Contradiction Detection

An LLM analyzes all 3 years of data and explicitly identifies reversals, policy shifts, and factual contradictions.

🧠

Dual-Layer Memory

Short-term memory tracks conversation state. Long-term memory fires alerts when new findings overturn past queries.

📊

Volatility Scoring

A confidence scorer rates how contradictory/volatile the topic is on a 0–100 scale using keyword heuristics.

📄

Structured Reports

Generates a 6-section "Temporal Evolution Brief" with timeline analysis and auto-exports it as a Markdown file.

Architecture

LangGraph State Machine

A cyclic directed graph where each node reads the shared state, performs its task, and writes back only what it changed.

🔎 search_years Tavily × 3 years
→
🧬 build_rag Chroma + Embeddings
→
⚡ detect_contradictions LLM Analysis
→
🛠️ execute_tools If contradiction found
↑ loops back once if contradiction found
📝 generate_report LLM writes brief
←
🧠 update_memory Long-term store
Node 1

Temporal Web Search

1

Query is Partitioned by Year

The user's query (e.g. "US global power") is sent to Tavily 3 times with the year appended: "US global power 2024 news"

2

Tavily Returns Live Web Data

Tavily is an AI-optimized search engine. It returns cleaned article content, not just links — perfect for feeding to an LLM.

3

Results Cleaned & Formatted

Code extracts only Title + Content + URL for each result, discarding raw metadata. Falls back to smart mock data if Tavily is unavailable.

4

Stored in State

Results are saved as years_data = {2024: "...", 2025: "...", 2026: "..."} and passed to the next node.

# For each of [2024, 2025, 2026]: results = tavily.invoke({ "query": "US global power 2024 news" }) # Extract clean text only for res in items[:3]: title = res.get("title") content = res.get("content") url = res.get("url") # years_data result: { 2024: "--- Results for 2024 ---\n Title: US Hegemony Challenged...\n Content: ...", 2025: "...", 2026: "..." }
Node 2

RAG Pipeline — Retrieval-Augmented Generation

✂️

Step 1: Chunk

Each year's search results are split into paragraphs (split by double newline). Chunks shorter than 20 chars are discarded.

🔮

Step 2: Embed

Every chunk is converted into a 1536-dimensional vector using Gemini's embedding-001 model. Similar text → similar vectors.

🔵

Step 3: Store

All chunks + their vectors are stored in ChromaDB (in-memory vector database) with year metadata attached.

🎯

Step 4: Retrieve

The user query is embedded and compared against all stored vectors. The top 5 most similar chunks are retrieved semantically.

💡 Why RAG? Raw search data can be 3000+ words. RAG uses semantic similarity to find only the most relevant paragraphs — so the LLM sees focused, useful context instead of noise.

Node 3 — Prompt 1

Contradiction Detection

⚡ Contradiction Detection Prompt (sent to LLM)
Analyze this data from [2024, 2025, 2026].
Look for contradictions or reversals.
If you see clear disagreements between years, output 'CONTRADICTION_FOUND'.
Otherwise output 'NO_CONTRADICTION'.

Data: [top 5 RAG chunks — first 2000 characters]
✅

If "CONTRADICTION_FOUND"

The LLM's full response is saved to contradictions[]. The graph routes to execute_additional_tools for deeper fact-checking.

➡️

If "NO_CONTRADICTION"

The contradictions[] list stays empty. The graph skips tools and routes directly to update_memory → generate_report.

Node 4

Agent Tools

🔎

web_search_temporal (query, year)

Searches Tavily for the query in a specific year. Called automatically 3× by search_all_years. Falls back to smart mock data if API unavailable.

✅

fact_check_db_lookup (claim)

Takes the RAG context and cross-checks it with Tavily fact-checking searches. Only runs when a contradiction is detected.

📊

confidence_scorer (analysis)

Counts volatility keywords (however, but, reversed, changed, debate...) in the context. Returns a score from 50–100. Simple but effective heuristic.

💾

export_report (content)

Writes the final report to chronos_latest_report.md on disk. Called automatically after every query. Also available as a download in Streamlit.

Node 5

Dual-Layer Memory System

SHORT-TERM

MemorySaver

Built into LangGraph. Saves the full ChronosState (messages, results, contradictions) after every node. Keyed by thread_id.


Purpose: In-conversation continuity. Lets the graph resume from a crash. Shared between turns in the same session.


Limitation: Wiped when the app restarts (in-memory only).

+
LONG-TERM

InMemoryStore

A key-value store that persists across different queries in the same session. Namespace: ("memories", "global_user") → key "history".


What it stores per query:

{ timestamp, query, contradiction: True/False }

Memory Alert fires when: previous query is similar AND its contradiction status differs from the current one.

Node 6 — Prompt 2

Final Report Generation

📝 Final Report Prompt (sent to LLM)
You are a financial/historical analyst. Write a detailed 'Temporal Evolution Brief' for: '{query}'.
Cover the timeline from {years}.
Structure your report:
  1. **Overview**
  2. **2024 Baseline**
  3. **2025 Transition**
  4. **2026 Current Reality**
  5. **Contradictions Found**
  6. **Final Verdict**

DATA:
[Raw search results from all 3 years + top 5 RAG chunks — first 3000 characters]
The 6-section structure forces the LLM to address each year separately and explicitly call out contradictions — preventing it from giving a single static answer.
Core Data Structure

ChronosState — The Shared Whiteboard

Every node reads from and writes to this shared state dictionary. Nodes only update the keys they care about.

class ChronosState(TypedDict): messages: # Full LangGraph message history (auto-appended) query: "Is the US losing global power?" # User question years_data: # {2024: "search text...", 2025: "...", 2026: "..."} rag_context: # Top-5 semantically relevant chunks with year labels contradictions: # ["CONTRADICTION_FOUND — In 2024..."] or [] memory_alert: # "🧠 MEMORY ALERT: ..." or "" final_report: # The full 6-section markdown report text iteration_count: # 0 → 1 (prevents infinite contradiction loops)
💡 iteration_count is the loop guard — when a contradiction is found, the graph loops back through RAG at most once. Without this, the graph would loop infinitely every time a contradiction is detected.

End-to-End

Complete Data Flow

1

User asks: "Is the US losing global power?"

Query enters via Streamlit text input or CLI. Passed into app.invoke() with iteration_count: 0.

2

Tavily searches for 2024, 2025, 2026 news

3 API calls. Clean text results stored in years_data dict.

3

Gemini embeds chunks → ChromaDB → semantic search

Top 5 most relevant chunks retrieved. rag_context updated with year labels.

4

LLM detects: CONTRADICTION_FOUND

Groq/Gemini analyzes RAG context. Graph routes to execute_tools.

5

Tools run: fact-check + volatility score

Loops back through RAG once for enriched context. iteration_count → 1.

6

Memory updated → Report generated

LLM writes 6-section "Temporal Evolution Brief". Exported to .md. Displayed in Streamlit tabs.
